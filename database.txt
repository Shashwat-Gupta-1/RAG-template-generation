### 3a. Database models (`backend/database/models.py`)

Three tables only:

```python
class User(Base):
    __tablename__ = "users"
    id: UUID (pk, default=uuid4)
    email: str (unique, indexed)
    name: str
    hashed_password: str
    role: str (default "user")
    is_active: bool (default True)
    created_at: datetime

class Conversation(Base):
    __tablename__ = "conversations"
    id: UUID (pk, default=uuid4)          # THIS is also the LangGraph thread_id
    user_id: UUID (fk -> users.id, cascade delete)
    title: str
    conversation_type: str (default "single")   # "single" | "bulk" | "creation_agent"
    template_folder: str | None
    template_id: str | None
    created_at: datetime
    updated_at: datetime (onupdate=utcnow)

class Message(Base):
    __tablename__ = "messages"
    id: UUID (pk, default=uuid4)
    conversation_id: UUID (fk -> conversations.id, cascade delete)
    role: str                    # "user" | "assistant"
    content: str
    output_file_path: str | None
    template_used: str | None
    created_at: datetime
```

Do NOT add a `conversation_state` / agent-state table. Agent state for the
creation-agent flow is owned entirely by the LangGraph Postgres checkpointer
(Section 4), keyed by `conversation.id` as `thread_id`. The `messages` table
is display-only — it is what the sidebar/chat UI renders, never what the
agent reads to resume.

### 3b. `backend/database/session.py`

Standard async SQLAlchemy setup: `create_async_engine(settings.database_url)`,

### 3c. `backend/auth/security.py` and `dependencies.py`

Standard JWT + bcrypt implementation:

- `create_access_token(data: dict) -> str` using `python-jose`, expiry from

- `get_admin_user`: wraps `get_current_user`, 403 if `role != "admin"`

### 3d. `backend/services/history_service.py`

Pure functions, each taking an `AsyncSession` — this is the **only** module
allowed to write to `conversations`/`messages`. All routes (auth, history,
agent, and the edits to `generate.py`/`bulk.py`) go through this, not raw
SQLAlchemy calls scattered around routes.

async def create_conversation(db, user_id, title, conversation_type="single",

async def list_conversations(db, user_id, limit=50) -> list[Conversation]

## 4. Refactor `backend/phase2/create_agent.py` — add LangGraph checkpointer

Current state: `_build_graph()` compiles with `graph.compile()` (no
checkpointer), and `SessionAgent` holds `conversation_history`, `assumptions`,
etc. as plain Python instance attributes, kept alive only by Streamlit's
`st.session_state`. This does not survive a server restart and has no
relationship to any conversation_id in Postgres.

Required changes:

1. Add a module-level function `get_checkpointer()` that returns an
   `AsyncPostgresSaver` connected via `settings.langgraph_db_url`, calling
   `.setup()` once (idempotent — safe to call on every app startup).
2. Compile the graph with `graph.compile(checkpointer=checkpointer)` instead
   of `graph.compile()`.
3. Every `.invoke()` / `.ainvoke()` call must pass
   `config={"configurable": {"thread_id": conversation_id}}` where
   `conversation_id` is the same UUID as the `Conversation.id` row.
4. `SessionAgent` no longer needs to manually carry `conversation_history`
   across calls in Python attributes — the checkpointer restores it via
   `thread_id`. Keep `assumptions`, `generated_prompt`, `prompt_history`, etc.
   as return values threaded through `AgentState` (already the case), but
   stop relying on `self.conversation_history` as the source of truth;
   instead, read it back from the graph's checkpointed state when needed
   (`compiled_graph.aget_state(config)`).
5. Convert `SessionAgent`'s methods (`chat`, `rebuild_prompt`, `refine_prompt`,
   `generate_image`) to `async def`, since `AsyncPostgresSaver` requires an
   async graph invocation path (`ainvoke`, not `invoke`).
6. Do not change any node function (`_node_analyze`, `_node_build_prompt`,
   `_node_refine_prompt`) or their prompts — only the compile/invoke/state
   plumbing around them.

### `backend/routes/agent_routes.py`  — new, wraps `SessionAgent`

This is what lets Streamlit (and later Next.js) drive the creation agent
without importing it directly:

```python
POST /agent/conversations
    # creates a Conversation row (conversation_type="creation_agent"),
    # returns {conversation_id}

POST /agent/chat
    body: {conversation_id: str, message: str | None}
    -> calls SessionAgent.chat via agent_service, using conversation_id as
       thread_id, then calls history_service.add_message() for both the
       user message (if present) and the assistant reply
    -> returns {reply, assumptions, clarification_question, ready}

POST /agent/rebuild-prompt
    body: {conversation_id: str, assumptions: dict, user_edits: str}
    -> returns {generated_prompt}

POST /agent/refine-prompt
    body: {conversation_id: str, refinement_request: str}
    -> returns {generated_prompt}

POST /agent/generate-image
    body: {conversation_id: str}
    -> calls SessionAgent.generate_image(), then
       history_service.add_message(role="assistant", output_file_path=path)
    -> returns {image_path}
```

All routes require `current_user = Depends(get_current_user)` and must
verify the `conversation_id` belongs to that user before touching the graph
(reuse the ownership check pattern from `history_service`).

`backend/services/agent_service.py` holds the glue: given a `conversation_id`,
instantiate/reuse a `SessionAgent`, call its async methods with the right
`thread_id`, and return plain dicts — routes stay thin.
