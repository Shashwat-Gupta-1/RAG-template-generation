## Layer 1 — Indexer

Runs once at setup and after every template addition. Never needs to be touched after that.

```
Run: python backend/indexer/indexer.py

For each folder in templates/:
        ↓
Read every overlay.json inside it
        ↓
Merge all descriptions and tags
        ↓
Build embed_text:
tags (x2) + descriptions + tags comma-separated
        ↓
Write main.json to folder
        ↓
Embed main.json embed_text using
paraphrase-multilingual-MiniLM-L12-v2
        ↓
Store vector + main.json in ChromaDB
One vector per folder — not per template
        ↓
Print: "Indexed: holi (2 templates)"
```

When to run the indexer:
- First time setup
- After adding any new template
- After changing any overlay.json description or tags
- After Phase 2 zone mapper saves a new template (runs automatically)

## Layer 2 — RAG Search (Two Stage)

### Stage 1 — Direct embedding (always runs first, free, no LLM)

```
User prompt: "festival of colours poster for Rahul"
        ↓
sentence-transformers embeds prompt
→ vector [0.23, -0.41, 0.87, ...]
        ↓
ChromaDB compares against all folder vectors
(one vector per folder)
        ↓
Returns scores:
holi      0.91  ✓ above threshold
dussehra  0.43
eid       0.38
hiring    0.21
        ↓
Score above 0.70? → Yes → use result
Score below 0.70? → Stage 2
```

### Stage 2 — Constrained LLM classification (only when Stage 1 fails)

```
Stage 1 score was 0.65 — below threshold
        ↓
Get all folders from ChromaDB
(folder names + their tags — never hardcoded)
        ↓
Send to LLM with strict constraints:
"Pick only from this folder list.
 Return the folder name and the most
 relevant tags FROM THAT FOLDER ONLY.
 Never invent folder names or tags."
        ↓
LLM returns:
{
  "folder": "holi",
  "relevant_tags": ["spring", "festival", "colours", "greeting"]
}
        ↓
Both folder name and tags validated
against ChromaDB — whitelist enforced
        ↓
Build enriched query:
"holi spring festival colours greeting
 spring festival colours greeting"
        ↓
Stage 1 runs again with enriched query
score 0.94 → above threshold → use result
        ↓
If still below threshold → no_match
```

## Layer 3 — Field Split Rules

These rules never change. They apply to every single request.

### Single poster generation

```
For each overlay field:
        ↓
Type = image?
→ use uploaded photo directly
→ LLM never touches image fields
        ↓
Type = text, llm_can_invent = false?
→ LLM extracts value from prompt
→ If not found in prompt → null
→ null triggers needs_input response
        ↓
Type = text, llm_can_invent = true?
→ LLM generates appropriate value
→ Never returns null for these
```

### Bulk Excel generation

```
File-level check (runs once, hard errors):
        ↓
emp_id column exists? → No → REJECT BATCH
emp_id has blank cells? → Yes → REJECT BATCH
emp_id has duplicates? → Yes → REJECT BATCH
All overlay field IDs have exact matching
column names (case-insensitive)? → No → REJECT BATCH
Extra unrecognized columns? → Yes → REJECT BATCH
        ↓
Row-level check (runs per row, soft errors):
        ↓
For each overlay field in this row:
        ↓
Value present in Excel column? → copy directly, no LLM
Blank + llm_can_invent = true? → LLM generates per row
Blank + llm_can_invent = false? → SKIP this row
        ↓
emp_id is always reserved:
never sent to LLM
never rendered on poster
only used for output filename:
{template_id}_{emp_id}.png
```

## Layer 4 — LLM Rules

LLM is called in exactly these situations and no others.

```
Single generation:
→ fill all text fields from prompt
→ extract identity fields (name, position)
→ generate creative fields (greeting, tagline)
→ return null for missing identity fields

Bulk generation per row:
→ ONLY for cells that are blank
  AND field has llm_can_invent = true
→ Never for cells that have a value
→ Never for emp_id
→ Never for image fields

RAG Stage 2 (fallback only):
→ ONLY when Stage 1 score below 0.70
→ Constrained to existing folder names
→ Constrained to existing folder tags
→ Returns folder + relevant tags only

Never called for:
→ Column name mapping
→ Fuzzy matching
→ Any bulk field that has a value
→ Image fields
→ emp_id
```

### LLM retry logic

```
Attempt 1:
→ Call OpenRouter free model
→ Parse JSON response
→ Strip markdown fences
→ Extract first { to last }
        ↓
JSON parse fails?
→ Append stricter instruction
→ Attempt 2
        ↓
Attempt 2 fails?
→ Raise ValueError
→ Single: return 500 error
→ Bulk: mark row as failed in audit
        ↓
Rate limit error?
→ Wait 2^attempt seconds
→ Retry up to 3 times
        ↓
Connection error?
→ Return 503 service unavailable
```

## Layer 5 — Renderer Rules

```
Input:
- template dict (from overlay.json)
- overlay_values dict {"name": "Rahul", "greeting_line": "Happy Holi!"}
- output_path (new file, never original)
- uploaded_image_path (optional)

For each layer in overlay_layers:
        ↓
Type = text:
  1. Get text from overlay_values
  2. Detect Hindi (any \u0900-\u097F chars)
  3. Hindi detected + Poppins font?
     → Auto-upgrade to NotoSansDevanagari
  4. Auto-shrink loop:
     Start at font_size
     Reduce by 2 until text fits box width
     Never go below font_size_min
  5. Still too wide at min size?
     → Truncate with ellipsis
  6. Calculate position:
     align: left / center / right
     vertical_align: top / middle / bottom
  7. Draw text on image
        ↓
Type = image:
  1. No uploaded photo? → skip this layer
  2. Open uploaded photo
  3. Resize to box dimensions
  4. Shape = circle?
     → Apply circular alpha mask
     → Draw border ring if border_width > 0
  5. Paste onto template

Always:
- Open template.png as read-only
- Save to new output path — original never touched
- os.makedirs(output_dir, exist_ok=True) before saving
```

## Layer 6 — All Response Cases

### Single generation — every possible outcome

```
POST /generate

Case 1 — Empty prompt
→ HTTP 400 "Prompt cannot be empty"

Case 2 — No match found (template doesn't exist)
→ {
    "status": "no_match",
    "message": "No template found for your request",
    "trigger_phase2": true
  }
→ Streamlit shows "Create new template?" button
→ Clicking it opens Phase 2 zone mapper

Case 3 — Ambiguous prompt (multiple folders close in score)
→ {
    "status": "ambiguous",
    "matches": [
      {"folder": "holi", "display_name": "Holi", "score": 0.74},
      {"folder": "dussehra", "display_name": "Dussehra", "score": 0.71}
    ]
  }
→ Streamlit shows category picker buttons
→ User picks one → request resubmitted with folder locked

Case 4 — One folder matched, multiple designs inside
→ {
    "status": "gallery",
    "folder": "holi",
    "display_name": "Holi",
    "templates": [
      {"template_id": "holi01", "description": "Modern design"},
      {"template_id": "holi02", "description": "Traditional design"}
    ]
  }
→ Streamlit shows design cards
→ User picks one → request resubmitted with template_id locked

Case 5 — Required field missing from prompt
→ {
    "status": "needs_input",
    "missing_fields": ["name"],
    "template_id": "holi01",
    "folder": "holi"
  }
→ Streamlit shows form for missing fields
→ User fills form → request resubmitted with extra fields

Case 6 — AI service down
→ HTTP 503 "AI service unavailable"
→ Streamlit shows retry button

Case 7 — Success
→ FileResponse — PNG file
→ Streamlit shows image + download button
```

### Bulk generation — every possible outcome

```
POST /bulk

Case 1 — Wrong file format
→ HTTP 422 "Could not read file. Upload .xlsx or .csv"

Case 2 — emp_id column missing
→ HTTP 422 "Column emp_id is required. Found: [name, city]"

Case 3 — Blank emp_id cells
→ HTTP 422 "Blank emp_id at rows: [5, 12, 23]"

Case 4 — Duplicate emp_ids
→ HTTP 422 "Duplicate emp_id values: [EMP001, EMP045]"

Case 5 — No template match
→ {"status": "no_match", "trigger_phase2": true}

Case 6 — Ambiguous folder match
→ {"status": "ambiguous", "matches": [...]}
→ User must pick folder before bulk runs

Case 7 — Multiple designs in folder
→ {"status": "gallery", "templates": [...]}
→ User must pick one design before bulk runs

Case 8 — Missing required columns
→ {
    "status": "column_mismatch",
    "missing_required_columns": ["name", "position"],
    "unrecognized_columns": ["employee_name", "job_title"],
    "all_required_columns": ["emp_id", "name", "position"]
  }
→ Streamlit shows exactly what to rename

Case 9 — Job queued successfully
→ {
    "status": "queued",
    "job_id": "abc123",
    "total_rows": 50
  }
→ Streamlit polls /job-status/{job_id} every 2 seconds
→ Shows live progress bar

Case 10 — Row skipped (blank non-inventable field)
→ Row skipped silently
→ Logged in audit CSV and skipped_rows.json
→ Batch continues with all other rows

Case 11 — Render fails for one row
→ Row marked as failed_render in audit CSV
→ Batch continues with all other rows

Case 12 — Job complete
→ {
    "status": "done",
    "total": 50,
    "completed": 47,
    "skipped": 2,
    "failed": 1
  }
→ Streamlit shows summary + download ZIP button
→ ZIP contains:
   - All successfully rendered PNGs
   - audit.csv (every row, status, timestamp)
   - skipped_rows.json (which rows, which fields, why)
```

## Layer 8 — Font Handling

```
Any text field in renderer:
        ↓
Detect script:
Any character in \u0900-\u097F range?
→ Hindi/Devanagari detected
        ↓
Hindi detected + font is Poppins?
→ Auto-upgrade to NotoSansDevanagari-Bold
→ Log: "Hindi detected — upgrading font"
        ↓
Hindi detected + font is NotoSans?
→ Auto-upgrade to NotoSansDevanagari-Bold
        ↓
No Hindi detected?
→ Use font exactly as specified in overlay.json
        ↓
Font file not found?
→ Try NotoSans-Regular as fallback
→ Log warning
→ Never crash
```

Font files required in fonts/:
```
Poppins-Regular.ttf      ← English body text
Poppins-Bold.ttf         ← English headings
Poppins-SemiBold.ttf     ← English poster titles
NotoSans-Regular.ttf     ← Mixed English/Hindi fallback
NotoSans-Bold.ttf        ← Mixed bold fallback
NotoSansDevanagari-Bold.ttf  ← Pure Hindi text
```

## Rules Summary — The Complete Set

### RAG rules
- One vector per folder in ChromaDB, not per template
- main.json auto-generated every time indexer runs
- embed_text = tags twice + descriptions + tags comma-separated
- Stage 1 always runs first — direct embedding, no LLM cost
- Stage 2 only runs when Stage 1 score below 0.70
- Stage 2 constrained — LLM can only pick from existing folder names and existing tags
- Both folder name and tags validated against ChromaDB whitelist after LLM returns
- Ambiguous = top two scores within 0.08 of each other → show category picker
- No match after both stages → trigger Phase 2

### Field rules
- emp_id always reserved — never in overlay.json, never to LLM, never rendered
- Bulk: exact column name match required, case-insensitive, no fuzzy matching
- Bulk: missing column → hard error, reject entire batch
- Bulk: blank value + llm_can_invent=false → soft error, skip row, continue batch
- Bulk: blank value + llm_can_invent=true → LLM generates for that cell only
- Bulk: value present → copy directly, zero LLM cost
- Single: all fields go to LLM — extract identity, generate creative
- Image fields → uploaded photo always, LLM never

### Renderer rules
- Original template.png never modified
- Hindi auto-detected by Unicode range \u0900-\u097F
- Hindi detected → auto-upgrade Poppins/NotoSans to NotoSansDevanagari
- Auto-shrink from font_size down to font_size_min in steps of 2
- Still too wide at min size → truncate with ellipsis
- Missing uploaded photo → skip image layer silently, do not crash
- output/ created with exist_ok=True before every render

### Indexer rules
- Run after any template addition or description change
- Safe to re-run multiple times — always overwrites cleanly
- Validates every overlay.json before indexing
- Rejects: missing required keys, base_image not found, description under 10 words, font_size_min >= font_size
- Skips folders with no valid templates, prints SKIP message

### Phase 2 rules
- Preview render mandatory before Save button activates
- Template ID must have no spaces
- Description must be at least 10 words
- At least one box must be drawn
- No overlapping boxes
- No duplicate field IDs within one template
- Indexer runs automatically after save — no developer action needed
- New template immediately searchable after save
