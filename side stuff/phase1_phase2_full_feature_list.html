Phase 1 Core template generation pipeline
Template storage and retrieval
RAG-based template search
ChromaDB stores template descriptions as vectors. User prompt is embedded and compared via cosine similarity. Returns the closest matching template — not by keyword but by meaning.
Phase 1
Overlay JSON schema per template
Every PNG has a paired JSON defining editable fields with box coordinates (x, y, width, height), full style block (font, size, weight, colour, align, letter-spacing), and llm_can_invent flag.
Phase 1
Indexing script
One-time script that reads every overlay.json, embeds description + tags, and saves vector + full JSON to ChromaDB. Re-run only when a new template is added.
Phase 1
Field filling intelligence
Field split engine
For each overlay field: if data is available (from Excel or prompt) it copies directly. Only sends genuinely missing fields to the LLM. Saves cost and prevents LLM from altering names.
Phase 1
Claude API overlay fill
LLM receives only editable field IDs + instructions + user prompt. Returns a flat JSON of field values only. Never sees coordinates, font sizes, or PNG data. System prompt enforces JSON-only output.
Phase 1
Confidence checker + fallback form
LLM returns null for fields it cannot extract (e.g. name not in prompt). System detects nulls and shows a fallback form in Streamlit asking the user to fill the missing values before rendering.
Phase 1
Fuzzy column mapping
When Excel column names differ from overlay field IDs (e.g. "employee_name" vs "name"), LLM maps them once at batch start. Direct copy then used for all rows. No repeated LLM calls for mapping.
Phase 1
Rendering
Pillow text renderer
Opens PNG read-only, draws text at box coordinates, uses font/colour/style from JSON. Auto-shrinks text from max to min font size until it fits the box width.
Phase 1
Image placeholder rendering
Uploaded photos resized to box dimensions, optionally circle-cropped, pasted at specified coordinates. LLM never involved with image fields.
Phase 1
Excel bulk loop + ZIP output
Pandas reads Excel. Template fetched once. LLM + renderer called per row. Each person gets a separate PNG. All zipped and returned to Streamlit for one-click download.
Phase 1
Immutable source files
Original PNG and overlay.json are always read-only. Only new output files are created. Template library is append-only — nothing is ever overwritten.
Phase 1
Frontend
Streamlit UI
Prompt input, optional profile photo upload, optional Excel upload. Single generate returns one PNG with preview + download. Bulk returns ZIP download. Progress bar for large batches.
Phase 1
Visual zone mapper
Developer tool — upload PNG, drag to draw placeholder boxes, configure colour/font/style per field, export complete overlay.json. No manual coordinate calculation needed.
Phase 1
Phase 2 Marketing agent and user template creation
Brand governance (developer-locked)
Brand config — set once, never user-changeable
Developer defines brand logo position, hex colour theme, and mascot inclusion rules. Every template created by the agent or user must follow these. Users cannot override. Stored in brand_config/ folder.
Phase 2
Admin panel
Developer-only UI to update logo, colour theme, and mascot rules. Changes propagate to all future agent-created templates without touching existing ones.
Phase 2
Creation agent flow
Template existence check
Before triggering the agent, RAG search runs first. If a match exists, it goes to template selection. Only if no match is found does the creation agent activate.
Phase 2
Conversational agent UI
Multi-turn conversation where agent proposes layout using brand config + user prompt. User reviews, requests changes, places placeholders via zone mapper, and confirms. Nothing saved until explicit approval.
Phase 2
Human approval loop
Agent shows final template with all placeholders before saving. User can request revisions — move a field, change font, adjust layout. Agent revises and shows again. Saved only on explicit confirm.
Phase 2
User-defined description and tags
After approval, user writes the RAG description and tags for their template. This is what ChromaDB uses for all future searches. Immediately indexed — available to all users from that moment.
Phase 2
User-uploaded template + zone mapper
User uploads their own PNG. Zone mapper tool lets them drag to draw placeholder boxes, pick text colour, font, weight, style, and letter spacing per field. Exports overlay.json automatically.
New feature
Multi-template selection and bulk
Template gallery — multiple matches shown
When ChromaDB finds multiple close matches, user sees a gallery and picks. Not forced to use the top result. Can select one for single generation or multiple for bulk.
Phase 2
Multi-template bulk generation
User selects multiple templates + uploads Excel. System generates one poster per template per person. 50 names × 2 templates = 100 output files. All zipped together.
Phase 2
LLM fills missing Excel fields
In bulk mode, columns present in Excel are copied directly. Fields missing from Excel are generated by LLM from context. No row fails due to incomplete data.
